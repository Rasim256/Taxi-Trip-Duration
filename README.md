# Taxi Trip Duration — предсказание длительности поездки такси по Нью-Йорку

Решение задачи [Kaggle: Taxi Trip Duration](https://www.kaggle.com/c/nyc-taxi-trip-duration) (NYC, 2016).  
Цель — предсказать длительность поездки такси в секундах по координатам, времени и служебным признакам.  
Метрика соревнования — **RMSLE**.

**Результат:** private score **0.36581** (RMSLE).

## Задача

- **Train:** ~1.46 млн строк, **Test:** ~625 тыс. строк.
- **Целевая переменная:** `trip_duration` (секунды).
- **Признаки:** координаты pickup/dropoff, datetime, `passenger_count`, `vendor_id`, `store_and_fwd_flag`.

Так как метрика — RMSLE, целевая переменная трансформирована через `log1p`, а предсказания возвращаются через `expm1`.

## Feature Engineering

Основной упор в проекте сделан на инженерию признаков — именно она дала основной прирост качества.

- **Расстояния:** haversine и манхэттенское расстояние между pickup и dropoff.
- **OSRM:** расстояние и время маршрута по дорожной сети (главный источник прироста — см. «Выводы»).
- **Погода:** данные о погоде в NYC на момент поездки.
- **Datetime-признаки:** час, день недели, месяц, выходные/праздники.
- **Координаты:** PCA-поворот координат, якоря и 40 центроидов (KMeans).
- **Комбинации признаков.**

## Очистка данных

- Удалены поездки с координатами, сильно удалёнными от Нью-Йорка.
- Удалены поездки с `passenger_count == 0` и `passenger_count >= 7`.

## Модель и валидация

- **Модель:** XGBoost (одна модель — после feature engineering признаков стало слишком много для сравнения многих моделей).
- **Валидация:** 5-fold KFold с OOF-предсказаниями.
- **Тюнинг:** Optuna с pruner'ами (early stopping на фолдах).
- **Ансамблирование:** не использовалось — одна модель, 5 фолдов, усреднение OOF.

## Выводы

- **OSRM дал самый большой прирост** среди всех признаков — дорожное расстояние и время маршрута значительно информативнее прямого haversine.
- Log-трансформация таргета критична для RMSLE.
- Инженерия признаков оказалась самой сложной и самой ценной частью проекта: большое количество признаков требует аккуратной валидации, чтобы не поймать утечку.
